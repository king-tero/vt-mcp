# vt-mcp 0.3.0 — remote HTTP connection

Connect an MCP client directly to `https://ai.virustotal.com/mcp` and retrieve existing reports for file hashes, URLs, domains and IPs without installing vt-mcp or Python locally. The connection uses a VTAI token in `x-apikey`, configured outside the model through the client's environment. Local stdio remains available with the same four tools.

Codex has completed all four report queries directly against the production HTTP endpoint. The [client validation matrix](../clients.md#validation-levels) distinguishes that workflow from installation of a local package. Follow the [current installation guide](../../README.md#install-for-local-stdio) for versioned releases.

## Get connected

1. Reuse protected VTAI access, or use [the connection page](https://ai.virustotal.com/connect/mcp) to create it explicitly once. Basic use is free within VTAI's rights and quotas and does not need a VirusTotal API key.
2. Apply the [Codex HTTP configuration](../clients.md#codex-cli--remote-http): `env_http_headers` maps `x-apikey` to an environment-variable name. Keep token values out of prompts, tool arguments, URLs and configuration examples.
3. Confirm the four tools and make an explicit existing-report query. Diagnostics consume shared quota; a missing report or service error is not a safety verdict.

Disconnecting a client does not revoke its token. Use the connection page's revocation action and require HTTP 204 to confirm it; REST and MCP then reject that credential. An already admitted lookup may finish. OAuth, hosted ChatGPT/Claude connectors and catalog publication are outside this release.

## Package changes

VTAI embeds the tools using a reader bound to each tool call. The local CLI and `create_server(settings, transport=...)` retain their existing behavior.

- Add `ReportReader` and `create_report_server(*, lifespan, bind_reports)` without adding tools or credential arguments.
- Share pure report validation, minimization, source/date/coverage presentation and semantic error mapping between HTTP and direct readers.
- Preserve valid HTTP-date retry delays on quota errors, with bounded conversion to seconds.
- Sanitize binding and reader failures; a missing request context cannot select a shared fallback reader.
- Exercise synthetic concurrent request isolation, direct/local tool parity and the existing stdio regression suite.

VTAI owns authentication, revocation, admission controls and deployment. This factory does not supply OAuth or deploy a service. A local package update and a remote deployment have separate installation requirements.

Codex CLI 0.153.4 with gpt-6-astra / xhigh completed four real production queries using the exact 0.2 stdio candidate. It then completed all four directly over production HTTP, without a local vt-mcp process or Host override. An independent review of captured events confirmed the sequence and the final answer's source, dates and coverage. The earlier local synthetic HTTP test remains separate evidence. See the [client matrix](../clients.md#validation-levels) for exact scope and limits; no other host inherits that validation.

Full URLs are disclosed to VTAI and VirusTotal; query a domain when that scope is sufficient. Report text remains untrusted evidence and unknown indicators never initiate scans. No result guarantees safety.

For local rollback, reinstall a previously verified wheel and restart the client, keeping its existing credential file. Remote rollback is coordinated by VTAI and must preserve the authentication, revocation and admission controls already enabled in the backend; reverting this package alone does not restore a service deployment.
