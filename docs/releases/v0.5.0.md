# v0.5.0 — Submit a file and retrieve its selected analysis

Submit an explicitly authorized file through the local CLI, keep a durable receipt and retrieve the selected analysis through CLI, REST or the read-only MCP tool `get_analysis(analysis_id)`. The four existing report tools and shared client setup remain available. The [service and workflow table](../clients.md#service-and-workflow-validation) distinguishes staging recovery, production acceptance and the target package release.

The submission command requires visible consent to standard VirusTotal sharing and limits files to 32,000,000 bytes. Automation supplies both the expected SHA-256 and explicit sharing consent. The client records its recovery reference before POST; ambiguous outcomes are recovered by reading the receipt, without repeating submission. VTAI owns authorization, quota, admission and the association between actor, hash and upstream analysis. Neither `submitted` nor a successful CLI exit means the analysis has completed.

Use the [analysis guide](../analysis.md) for consent, polling, statuses and recovery. The MCP tool reads only an analysis registered to the current actor; it does not upload, accept a local path or wait for completion. A missing or failed report is never treated as a safety verdict or permission to upload. Standard submission is not Private Scanning.

A deployment must retain the compatible VTAI analysis routes before this flow is available. Service rollback preserves receipt records and the existing MCP authentication and revocation controls; it does not repeat or undo an upstream submission. Package installation follows the [README](../../README.md), with exact checksums from the published release.
