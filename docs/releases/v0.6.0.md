# v0.6.0 — Check one Python execution in Codex

This version was developed privately. Use the [README](../../README.md) for the current public release.

Version 0.6.0 adds an optional check before one supported Python command runs in Codex. Use a verified wheel from [GitHub Releases](https://github.com/king-tero/vt-mcp/releases); the [validation matrix](../clients.md#service-and-workflow-validation) distinguishes earlier host checks, analysis workflows and versioned release verification.

The optional `vt-mcp guard` hook recognizes one documented command form:

```text
/usr/bin/python3 -I /absolute/path/script.py
```

It replaces that command with a runner that copies the main script, seals the copy as non-executable data, queries its SHA-256 through VTAI and gives those same bytes to the fixed Python interpreter when policy permits. It does not depend on a model choosing an MCP tool, upload the script or scan imports and dependencies. Commands outside the grammar pass through unchecked; a disabled, untrusted or skipped hook provides no interception.

Control mode blocks adverse, unknown, insufficient and unavailable evidence. Observe mode reports that result and executes after valid preparation. Invalid or changed policy, preparation/platform failure and cancellation before start block both modes. Reports meeting policy are not guarantees of safety. The runner removes VTAI environment variables and closes HTTP before execution; it is not a sandbox against other same-user software or later script behavior.

The Linux seal correction uses stable UAPI values when a CPython build omits fcntl constants. Kernel seals, non-executable mode and descriptor verification remain mandatory, with no original-path or ordinary temporary-file fallback. Read the [scope, installation, normal hook trust and policy guide](../control.md).

| Existing evidence | Exact scope |
|---|---|
| Earlier local guard candidate | 20 accepted Codex CLI 0.153.4 / gpt-6-astra xhigh cases with normal UI trust, both modes and harmless loopback fixtures |
| Corrected e76 CI candidate | CI passed Python 3.12/3.13/3.14; 189 artifact comparisons and 32 installed tests; two real Codex control cases passed using a Python 3.14.7 runner |

The script interpreter in the corrected checks remained `/usr/bin/python3` 3.12.3. The observed host profile was `danger-full-access`; restrictive sandbox behavior, other hosts and broader command forms are not validated. No real VirusTotal lookup or external submission was part of those guard checks. [Client validation levels](../clients.md#optional-codex-execution-control) and [artifact distinctions](../control.md#observed-host-evidence) keep those observations separate from this updated package.

The five existing read-only MCP tools, explicit submission CLI, durable receipt recovery and both MCP transports retain their contracts. The hook adds no MCP tool. Bare `vt-mcp` still starts stdio; using the hook requires the reviewed local package, policy and an explicitly trusted definition. See the [0.5 analysis guide](../analysis.md) for consent and deployment requirements, and the [README](../../README.md#install-for-local-stdio) for versioned wheel installation.
