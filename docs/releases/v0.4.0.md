# v0.4.0 — Shared client setup and access

Version 0.4 adds shared client setup. These notes describe its changes; use the [current installation guide](../../README.md#install-for-local-stdio) for versioned releases and the [validation matrix](../clients.md#validation-levels) for observed workflows.

Version 0.4 distributes small configuration fragments for one common MCP server and documents free VTAI access, diagnosis, disconnect and revocation. Its runtime and four read-only report tools remain unchanged from the reviewed implementation. It adds no provider SDK, bridge, new authentication mechanism, upload tool or backend deployment.

- HTTP clients use `x-apikey` from their host environment, without a local Python or vt-mcp installation. Bearer/OAuth options do not authenticate VTAI.
- Codex, Claude Code and Gemini have setup instructions. Antigravity, Qwen, Kimi, OpenCode and applications using Z.ai/DeepSeek retain their actual validation levels.
- The source distribution includes guides and configuration examples; the wheel does not modify client settings.
- Access setup stays outside model context. The Bash file loader rejects a missing file or empty first line, including a newline-only file.

## Observed acceptance and limits

| Surface | Evidence retained | Scope not established by that evidence |
|---|---|---|
| Codex CLI 0.153.4 / gpt-6-astra xhigh | Four reports once each at the direct public HTTP endpoint, no local vt-mcp process | Negotiated wire version/internal retries were not captured; not a 0.4 package installation |
| Codex stdio | Exact 0.2 CI wheel with four real production reports | Installation of the final 0.4 release |
| Connection page in Chrome 146 | Real explicit registration, download request, diagnosis and revocation through a route pinned to the production candidate | Ordinary public-browser navigation and package release acceptance |
| Existing staging MCP/browser checks | Real report lookups, access denial/revocation and rollback checks | No new cloud or browser test was run for this document integration |
| Other clients and hosted connectors | Levels listed in the [client matrix](../clients.md#validation-levels) | Documentation/schema checks are not full client support; hosted OAuth/account tests remain pending |

Use the [access guide](../access.md), [client setup](../clients.md), and [configuration fragments](../../examples/client-configs/README.md). The existing connection route is `/connect/mcp`. Checking access consumes query quota; a download request does not prove protected storage, and a registration failure can be ambiguous.

The [service and workflow table](../clients.md#service-and-workflow-validation) keeps these observations separate from versioned release verification and analysis/CI requirements.
